# 本地一键运行（含局域网访问）

> 适用人群：只想"把 StyleFlow 跑起来"的使用者。不需要懂数据库、虚拟环境、Docker。
> 全程只需要安装 **Python** 和 **Node.js** 两样东西，其余交给 `start.py`。

---

## 1. 它是怎么跑起来的

```
浏览器 ──► http://本机IP:3000（前端 Next.js，唯一对外端口）
                │
                ├── /api/*    → Django 后端（仅监听本机 8000）
                ├── /media/*  → 上传与 AI 生成的图片
                └── /admin/*  → Django 管理后台
                        │
                        ├── 数据库：SQLite 文件（data/styleflow.sqlite3）
                        ├── 文件：本地磁盘（data/media）
                        └── AI 任务：进程内线程池（无需 Redis）
```

因为前后端"同源"（对外只有一个 3000 端口），所以**无论你用 localhost、局域网 IP 还是域名访问，都不需要改任何配置**，也不会出现跨域或图片 404。

---

## 2. 前置要求

| 依赖 | 版本 | 下载地址 | 备注 |
|---|---|---|---|
| Python | 3.12 或更高 | <https://www.python.org/downloads/> | Windows 安装时**必须勾选** `Add python.exe to PATH` |
| Node.js | 20 或更高 | <https://nodejs.org/> | Windows 可执行 `winget install OpenJS.NodeJS.LTS` |

检查是否安装成功（命令行执行）：

```bash
python --version
node --version
```

> 其余依赖（PostgreSQL / Redis / MinIO / 对象存储）**都不需要安装**。

## 3. 启动

### Windows

在项目文件夹里**双击 `start.bat`**，或在项目根目录打开 PowerShell：

```powershell
python start.py
```

### macOS / Linux

```bash
bash start.sh          # 等价于 python3 start.py
```

### 首次启动会自动完成

1. 找到（或创建）Python 虚拟环境并安装后端依赖
2. 生成运行配置 `.env`（随机密钥、SQLite、同源部署设置）
3. 安装前端依赖（`npm ci`）
4. 构建前端 —— **约 3-10 分钟，请耐心等待，不要关闭窗口**
5. 初始化数据库、收集后台静态资源
6. 创建管理员账号（用户名 `admin`，随机密码）
7. 启动后端 + 前端，等待就绪后自动打开浏览器

之后每次启动只需要几秒（依赖和构建产物都会复用）。

### 启动成功后的输出

```
  ✓ StyleFlow 已启动
    本机访问      http://127.0.0.1:3000
    局域网访问    http://192.168.1.23:3000   ← 同一 WiFi 下的手机/电脑可直接打开
    接口文档      http://127.0.0.1:3000/api/v1/docs
    管理后台      http://127.0.0.1:8000/admin/   (Django 管理后台，走「后端端口」)
    默认账号      admin / xxxxxxxxx
    数据目录      X:\project\StyleFlow\data
    日志          X:\project\StyleFlow\data\logs
    停止服务      Ctrl+C
```

管理员账号同时写入 `data/管理员账号.txt`，登录后请尽快修改密码。

### 停止

- 在同一个窗口按 `Ctrl+C`
- 或另开一个窗口执行 `python start.py --stop`

### 关于两个端口

| 端口 | 用途 | 说明 |
|---|---|---|
| **3000**（前端） | 页面 + API + 图片，全部同源 | 局域网/公网只需暴露这一个端口 |
| **8000**（后端） | Django 接口 + **管理后台** `/admin/` | 本机调试用；Django 后台以尾斜杠路由为基准，无法经前端代理（会形成重定向循环），因此后台固定走后端端口 |

也就是说：日常业务页面用 3000，需要 Django 原生的管理后台（用户/权限/数据维护）时用 `http://127.0.0.1:8000/admin/`，账号同样是 `admin` / 上面那个密码。

## 4. 命令行参数

| 参数 | 作用 |
|---|---|
| `--check` | 只做环境自检（Python/Node/依赖/端口/构建状态），不启动 |
| `--port 8080` | 更换前端端口（默认 3000） |
| `--backend-port 9000` | 更换后端端口（默认 8000，一般不用改） |
| `--local` | 仅允许本机访问，不监听局域网 |
| `--host 192.168.1.23` | 只绑定指定网卡地址 |
| `--dev` | 前端开发模式（不构建，改代码即时生效，页面首次访问稍慢） |
| `--rebuild` | 强制重新安装依赖并重新构建前端 |
| `--db postgres` | 使用 `.env` 中的 PostgreSQL 配置（见第 6 节） |
| `--reset-admin` | 重置管理员密码并打印新密码 |
| `--no-browser` | 启动后不自动打开浏览器 |
| `--stop` | 停止已启动的服务 |

## 5. 数据、备份与迁移

所有运行期数据都在 **`data/`**：

```
data/
├── styleflow.sqlite3     # 数据库（SQLite 模式）
├── media/                # 用户上传 + AI 生成的文件
├── static/               # Django admin 静态资源
├── logs/                 # backend.log / frontend.log
├── run/                  # 运行状态（PID、构建标记）
└── 管理员账号.txt         # 首次创建管理员时生成，可删除
```

- **备份**：把 `data/` 和 `.env` 复制走即可。
- **迁移**：在新机器的项目目录放入这两个东西，直接 `python start.py`。
- **重来一遍**：删除 `data/`（数据全清）或删除 `data/styleflow.sqlite3`（只清数据库）。

## 6. 局域网访问

默认启动时脚本监听 `0.0.0.0`，同一局域网（同一 WiFi/交换机）的设备即可访问。

### 步骤

1. 启动后记下终端打印的「局域网访问」地址，例如 `http://192.168.1.23:3000`
2. 让手机/同事电脑连上**同一个 WiFi**，浏览器打开该地址即可
3. 其他设备遇到的登录账号问题：让管理员在 `/admin/users`（或 Django 后台）里为同事创建账号

### 如果局域网打不开：放行防火墙

**Windows**（管理员身份打开 PowerShell 执行一次）：

```powershell
netsh advfirewall firewall add rule name="StyleFlow" dir=in action=allow protocol=TCP localport=3000
```

**macOS**：系统设置 → 网络 → 防火墙 → 选项 → 允许 `node` 接受传入连接。

**Linux（ufw）**：

```bash
sudo ufw allow 3000/tcp
```

### 常见排查

| 现象 | 原因 / 处理 |
|---|---|
| 只能本机打开 | 启动时加了 `--local`，或防火墙上未放行 |
| 手机上页面能开但图片不显示 | 一定是 `.env` 里的 `BACKEND_BASE_URL` 被填了绝对地址；清空它（脚本默认会清空） |
| 提示端口被占用 | 已有实例在跑：先 `python start.py --stop`，或用 `--port 8080` 换端口 |
| 家里路由器做了「AP 隔离」 | 关闭路由器的客户端隔离，或改用有线/热点方式 |

### 只想本机访问

```bash
python start.py --local
```

## 7. 进阶：换成 PostgreSQL / Celery / S3

默认配置（SQLite + 线程池 + 本地磁盘）已经能支撑单机与小型团队。需要更强并发时按需切换，**只改 `.env` 即可，代码无需变动**。

### 7.1 切换到 PostgreSQL

1. 准备一个 PostgreSQL 15+ 数据库
2. 编辑根目录 `.env`：

```ini
DATABASE_MODE=postgres
DB_NAME=styleflow
DB_USER=styleflow
DB_PASSWORD=你的密码
DB_HOST=localhost
DB_PORT=5432
```

3. 重新执行 `python start.py`（脚本会自动补装 `psycopg2-binary` 并迁移建表）

> 从 SQLite 迁移既有数据：`python backend/manage.py dumpdata --indent 2 > backup.json`（先切回 sqlite 导出），再切到 postgres 后 `loaddata backup.json`。

### 7.2 切换回 Redis + Celery

1. 安装并启动 Redis
2. 编辑 `.env`：

```ini
TASK_BACKEND=celery
REDIS_URL=redis://localhost:6379/0
```

3. 另开一个终端启动 worker：

```bash
cd backend
celery -A config.celery_app worker -l info
```

### 7.3 切换到 S3 / MinIO 对象存储

```ini
STORAGE_BACKEND=s3
MINIO_ENDPOINT=http://localhost:9000
MINIO_ACCESS_KEY=minioadmin
MINIO_SECRET_KEY=minioadmin
MINIO_BUCKET=styleflow
```

## 8. 开发者：不使用脚本手工启动

```bash
# 后端（config.settings.local = SQLite + 线程任务 + 同源媒体）
cd backend
# Windows:
..\.venv\Scripts\python.exe manage.py runserver 0.0.0.0:8000
# macOS/Linux:
../.venv/bin/python manage.py runserver 0.0.0.0:8000

# 前端（另开终端）
cd frontend
npm run dev
```

前端通过 `frontend/.env.local` 中的 `STYLEFLOW_BACKEND_ORIGIN` 决定代理目标（默认 `http://127.0.0.1:8000`）。
