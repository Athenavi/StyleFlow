# 公网 / 域名访问教程

> 前提：已经能通过 [本地一键运行](01-本地一键运行.md) 在本机正常使用。
> 本文覆盖四种让外网访问的方案，按推荐程度排序。
>
> ⚠️ **暴露到公网前请务必先完成 [第 5 节 安全清单](#5-安全清单必做)**。

StyleFlow 对外只需要一个端口：**前端 3000**（后端 8000 只监听本机，由前端反向代理）。
因此任何反向代理方案都只需把公网流量转到 `127.0.0.1:3000`。

---

## 1. 方案对比

| 方案 | 需要公网 IP | 需要域名 | HTTPS | 难度 | 适用场景 |
|---|---|---|---|---|---|
| **A. Caddy 自动 HTTPS** | 是 | 是 | 自动签发 | ★★ | 有域名和公网 IP，最推荐 |
| **B. Cloudflare Tunnel** | **否** | 可选 | 自动 | ★★ | 家宽/内网、临时演示、无公网 IP |
| **C. Nginx 反向代理** | 是 | 是 | 需自己配证书 | ★★★ | 已有 Nginx/服务器环境 |
| **D. 路由器端口映射** | 是 | 否 | 无 | ★ | 仅临时测试，不建议长期 |

---

## 2. 方案 A：Caddy 自动 HTTPS（推荐）

Caddy 会自动申请并续期 Let's Encrypt 证书，配置只有几行。

### 2.1 前置条件

1. 一个域名（如 `styleflow.example.com`），在域名商处添加 **A 记录** 指向你的公网 IP
2. 路由器/防火墙把 **80 和 443** 端口映射到这台机器
3. 确认没被运营商封禁 80/443（部分家宽会封）

### 2.2 安装 Caddy

```powershell
# Windows
winget install CaddyServer.Caddy

# macOS
brew install caddy

# Debian/Ubuntu
sudo apt install -y caddy
```

### 2.3 配置

在项目根目录新建 `Caddyfile`（可参考仓库中的 `deploy/Caddyfile.example`）：

```caddy
styleflow.example.com {
    encode gzip

    # Django 管理后台与它的静态资源（需要后台时保留；不需要可删掉这两个块）
    handle /admin/* {
        reverse_proxy 127.0.0.1:8000
    }
    handle /static/* {
        reverse_proxy 127.0.0.1:8000
    }

    # 其余全部交给前端（前端再同源代理 /api 与 /media）
    handle {
        reverse_proxy 127.0.0.1:3000
    }
}
```

### 2.4 修改 `.env`（关键）

公网必须让 Django 知道真实域名与 HTTPS：

```ini
# 域名访问白名单（逗号分隔）
CSRF_TRUSTED_ORIGINS=https://styleflow.example.com
ALLOWED_HOSTS=styleflow.example.com,127.0.0.1

# 通过反向代理提供 HTTPS 后打开以下三项
SECURE_SSL_REDIRECT=true
SESSION_COOKIE_SECURE=true
CSRF_COOKIE_SECURE=true
```

> `ALLOWED_HOSTS` 在本地模式下默认为 `*`；若你希望严格限制，可在 `.env` 中显式覆盖。

### 2.5 启动

```powershell
# 终端 1：只监听本机（让 Caddy 对外）
python start.py --local --no-browser

# 终端 2：启动 Caddy
caddy run --config Caddyfile
```

浏览器访问 `https://styleflow.example.com` 即可。首次访问时 Caddy 会在几秒内签发证书。

## 3. 方案 B：Cloudflare Tunnel（无需公网 IP）

适合家宽、内网、虚拟机：由 Cloudflare 建立出站隧道，外网通过 Cloudflare 的域名访问。

### 3.1 安装 cloudflared

```powershell
# Windows
winget install Cloudflare.cloudflared

# macOS
brew install cloudflared

# Linux（Debian/Ubuntu）
curl -fsSL https://pkg.cloudflare.com/cloudflare-main.gpg | sudo tee /usr/share/keyrings/cloudflare-main.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/cloudflare-main.gpg] https://pkg.cloudflare.com/cloudflared any main" | sudo tee /etc/apt/sources.list.d/cloudflared.list
sudo apt update && sudo apt install -y cloudflared
```

### 3.2 快速试用（临时随机域名）

```powershell
# 终端 1
python start.py --local --no-browser

# 终端 2
cloudflared tunnel --url http://127.0.0.1:3000
```

命令会打印一个 `https://xxxx-xxxx.trycloudflare.com` 地址，任何人都能通过它访问（**仅用于临时演示**）。

### 3.3 使用自己的域名（持久隧道）

```bash
cloudflared tunnel login                       # 浏览器里授权你的 Cloudflare 域名
cloudflared tunnel create styleflow            # 创建隧道，记下隧道 ID
cloudflared tunnel route dns styleflow styleflow.example.com
cloudflared tunnel run --url http://127.0.0.1:3000 styleflow
```

同样需要在 `.env` 中设置：

```ini
CSRF_TRUSTED_ORIGINS=https://styleflow.example.com
SECURE_SSL_REDIRECT=true
SESSION_COOKIE_SECURE=true
CSRF_COOKIE_SECURE=true
```

> 提示：Cloudflare 免费版上传限制约 100MB，StyleFlow 单文件限制 10MB，够用。

## 4. 方案 C：Nginx 反向代理

```nginx
server {
    listen 80;
    server_name styleflow.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name styleflow.example.com;

    ssl_certificate     /etc/letsencrypt/live/styleflow.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/styleflow.example.com/privkey.pem;

    client_max_body_size 20m;          # 媒体上传需要

    # Django 管理后台与静态资源（需要后台时保留）
    location /admin/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host              $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
    location /static/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host              $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;       # AI 生成任务可能较久
    }
}
```

`.env` 中的设置与方案 A 相同。若使用 `certbot`：`sudo certbot --nginx -d styleflow.example.com`。

## 5. 方案 D：只有公网 IP、没有域名

在路由器上把外网的 3000 端口映射到这台机器的 3000，直接访问 `http://公网IP:3000`。

**注意**：

- 没有 HTTPS，登录密码与 JWT 明文传输，**只适合内网或临时测试**
- 建议改成非默认端口，并配合 `ALLOWED_HOSTS` 限制
- 家用宽带 IP 通常会变化，需要 DDNS

## 6. 安全清单（必做）

- [ ] **修改默认管理员密码**（用 `python start.py --reset-admin` 或登录后在界面修改）
- [ ] 删除或保管好 `data/管理员账号.txt`
- [ ] 生产环境把 `.env` 中 `DJANGO_DEBUG` 改为 `false`
- [ ] 一定通过 HTTPS 对外（方案 A/B/C），并打开 `SECURE_SSL_REDIRECT`、`SESSION_COOKIE_SECURE`、`CSRF_COOKIE_SECURE`
- [ ] 设置 `CSRF_TRUSTED_ORIGINS` 为你的真实域名
- [ ] 后端 8000 端口只对内网/反向代理开放：推荐用 `python start.py --local` 让前后端都只监听 127.0.0.1，由反向代理对外提供 443；不需要 Django 后台时，反代里可以不转发 `/admin/`、`/static/`
- [ ] 定期备份 `data/`（数据库 + 图片）
- [ ] 多人使用建议切换 PostgreSQL（见 [01-本地一键运行.md#71-切换到-postgresql](01-本地一键运行.md)）

## 7. 公网常见报错

| 报错 / 现象 | 原因与处理 |
|---|---|
| `CSRF verification failed` | `.env` 里 `CSRF_TRUSTED_ORIGINS` 没写或域名不一致（必须带 `https://`） |
| `DisallowedHost` | 若你显式设置了 `ALLOWED_HOSTS`，把域名加进去 |
| 页面打开但登录 401 | 浏览器缓存了旧 token：清掉 localStorage 后重新登录 |
| 图片 404 | 确认 `.env` 的 `BACKEND_BASE_URL` 为空（同源相对路径） |
| Mixed Content 警告 | 页面走 HTTPS 但图片是 HTTP：同样是 `BACKEND_BASE_URL` 被填了绝对 HTTP 地址 |
| 重定向循环 | `SECURE_SSL_REDIRECT=true` 但反代没有传 `X-Forwarded-Proto`（方案 C 的配置里有） |
| 上传大图失败 | 反向代理的 `client_max_body_size` 太小 |
| AI 生成中途断开 | 反代超时太短，请设置 `proxy_read_timeout 300s` |
