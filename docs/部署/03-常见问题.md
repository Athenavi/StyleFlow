# 常见问题（FAQ）

> 遇到问题时，第一站是日志：`data/logs/backend.log`、`data/logs/frontend.log`。
> 也可以先运行 `python start.py --check` 做一次环境自检。

---

## 1. 启动相关

### 端口被占用

```
× 前端端口 3000 已被其它程序占用
```

- 如果 StyleFlow 已经在运行：先 `python start.py --stop`
- 如果是别的程序占用：换端口 `python start.py --port 8080`
- 查看谁占用了端口（Windows）：`netstat -ano | findstr :3000`

### 提示"未检测到 Python"或版本过低

- 安装 Python 3.12+：<https://www.python.org/downloads/>
- Windows 安装时务必勾选 **Add python.exe to PATH**，装完后重新打开命令行
- 验证：`python --version`
- 若系统里有多个 Python，可指定解释器：`set PYTHON=C:\Python312\python.exe` 后运行 `start.bat`（Linux/macOS：`PYTHON=python3.12 bash start.sh`）

### 提示"未检测到 Node.js"

- 安装 Node.js 20+：<https://nodejs.org/>
- Windows 一条命令：`winget install OpenJS.NodeJS.LTS`
- 验证：`node --version`

### 卡在"正在安装依赖"或"正在构建前端"

- 首次安装依赖 + 构建前端确实需要 3-10 分钟，属正常现象（终端会有输出，不要关闭窗口）
- 依赖下载慢可以换国内镜像：

```bash
# npm
npm config set registry https://registry.npmmirror.com

# pip（虚拟环境内执行）
backend\.venv\Scripts\python.exe -m pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

- 中断后重新执行 `python start.py` 会继续，不会重复劳动

### 前端构建失败 / 前端行为异常

```bash
python start.py --rebuild
```

会重新安装前端依赖并重新构建。

### 后端启动后立刻退出

查看 `data/logs/backend.log` 末尾的报错。常见原因：

- `.env` 里数据库配置写了 `DATABASE_MODE=postgres` 但 PostgreSQL 没启动 → 改回 `sqlite` 或先启动数据库
- 端口被占用（见上）

## 2. 登录与账号

### 忘记管理员密码

```bash
python start.py --reset-admin
```

会重置 `.env` 中 `STYLEFLOW_ADMIN_USER`（默认 `admin`）的密码，并在终端打印新密码、写入 `data/管理员账号.txt`。

### 新建的普通账号登录后看不到某些菜单

菜单由角色决定。用管理员账号进入 `/admin/users`（或 Django 后台 `/admin/`）把角色改成 `admin` / `designer` / `pattern_maker` / `accountant` / `erp_sync`。

### 打开页面被踢回登录页

Access Token 默认 30 分钟过期，前端会自动用 refresh token 续期；若 refresh token 也过期（7 天），重新登录即可。浏览器清了站点数据也会导致需要重新登录。

## 3. 图片与媒体库

### 图片显示不出来（裂图）

99% 的原因是 `.env` 里的 `BACKEND_BASE_URL` 被填了 `http://localhost:8000` 之类的地址：

```ini
# 必须留空（同源相对路径），图片才能在本机 / 局域网 / 域名下都正常显示
BACKEND_BASE_URL=
```

`start.py` 每次启动都会把它清空；如果你手工改过 `.env`，请检查这一项。

### 上传提示"文件超过 10MB"

单文件上限 10MB（JPG/PNG/WebP/GIF）。压缩后可重试。

### 删除的文件去哪了

「删除」是移入回收站（磁盘上位于 `data/media/.trash/`），在媒体库的回收站里可以恢复或永久删除。

## 4. AI 功能

### 点"AI 生成"后长时间无结果或报错

AI 生成需要你自己提供模型服务，二选一：

- **云端**：在 `.env` 填 `OPENAI_API_KEY` / `CLAUDE_API_KEY` / `TONGYI_API_KEY`，或登录后在「AI 配置」页面为当前用户填写
- **本地**：自行部署 Stable Diffusion WebUI（带 `--api`），并把 `SD_WEBUI_URL` 指向它（默认 `http://localhost:7860`）

没有配置时，其它功能（用户、媒体库、工作流、工艺单、核工价…）依然可以正常使用。

### 生成任务一直"处理中"

- 查看 `data/logs/backend.log`
- 如果是 SD WebUI：确认它已启动且开了 API（访问 `http://localhost:7860/docs` 能打开）
- 生成通常需要几十秒到几分钟，页面最长会轮询 120 秒

### 虚拟试衣结果就是原图

当前内置实现为**模拟流程**（返回人物原图），接入真实 VTON 模型（IDM-VTON / OOTDiffusion）后才会输出合成图。

## 5. 数据与数据库

### 数据存在哪里，怎么备份

`data/` 目录：`styleflow.sqlite3`（数据库）、`media/`（图片）、`logs/`（日志）。备份这两个文件夹即可：`data/` + `.env`。

### 想清空所有数据重来

```bash
# Windows
rmdir /s /q data
# macOS / Linux
rm -rf data
```

再重新 `python start.py`（会重建数据库与管理员账号）。

### 想从 SQLite 换成 PostgreSQL 并带走数据

```bash
# 1) 当前 SQLite 下导出
cd backend
..\.venv\Scripts\python.exe manage.py dumpdata --indent 2 --exclude contenttypes --exclude auth.permission > ..\backup.json

# 2) 改 .env：DATABASE_MODE=postgres + DB_* 信息

# 3) 建表并导入
..\.venv\Scripts\python.exe manage.py migrate --noinput
..\.venv\Scripts\python.exe manage.py loaddata ..\backup.json
```

### ERP 页面点同步报"未配置 ERP 数据库"

ERP 是可选集成。需要在 `.env` 中填写 `ERP_DB_HOST` / `ERP_DB_NAME` / `ERP_DB_USER` / `ERP_DB_PASSWORD` / `ERP_DB_PORT` 后再同步。

## 7. 其它

### 中文显示乱码

把终端切到 UTF-8：Windows PowerShell 执行 `chcp 65001`；旧版 cmd 窗口可能显示异常，建议使用 Windows Terminal。

### 如何完全卸载 / 清理项目

可以安全删除以下目录（都可重新生成）：

```
.venv/                  # 项目根的虚拟环境（若存在）
backend/.venv/          # 脚本创建的虚拟环境
frontend/node_modules/  # 前端依赖
frontend/.next/         # 前端构建产物
data/                   # 所有业务数据（删除即清空数据）
```

### 端口的对外关系

| 端口 | 作用 | 是否需要对外暴露 |
|---|---|---|
| 3000 | 前端页面（同时代理 API 与图片） | 局域网/公网只需暴露它 |
| 8000 | Django API 与 **管理后台 `/admin/`** | 本机/内网使用；公网用反代（见 02 文档） |

### 为什么 Django 管理后台在 8000 端口，而不是 3000？

Django 后台的 URL 都是"尾斜杠路由"（`/admin/`、`/admin/login/`），而前端所用的 Next.js 反向代理在转发时会规范化掉尾斜杠，直接代理会形成 301 无限重定向。因此后台固定走后端端口：

- 本机：<http://127.0.0.1:8000/admin/>
- 局域网：<http://主机IP:8000/admin/>（后端默认监听 0.0.0.0；用 `--local` 启动则仅本机可访问）
- 公网：用 Caddy/Nginx 把 `/admin/`、`/static/` 转发到 8000（配置见 [02-公网访问教程.md](02-公网访问教程.md)）

日常业务完全不需要它——业务页面、图片、接口都在 3000 端口同源工作。

### 想要更省心的部署方式

如果目标机器上已经装了 Docker，也可以自行用容器方式部署；本项目默认的零配置脚本面向"不想折腾"的本地场景，两种方式的数据目录互不影响。
